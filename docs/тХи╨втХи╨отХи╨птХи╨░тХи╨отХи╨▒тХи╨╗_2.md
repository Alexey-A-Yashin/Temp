## 3. РАСТИТЕЛЬНОСТЬ: ОДИН ВИД НА ПОЯС — ЭТО РЕШЕНИЕ ИЛИ НЕДОДЕЛКА

`RingVegetationPlacer.KindFor`:

```csharp
BiomeType.Forest    => VegetationKind.Pine,
BiomeType.Shrubland => VegetationKind.Bush,
BiomeType.Grassland => VegetationKind.GrassTuft,
_                   => null,      // вода, скала, снег, пляж — голые
```

При этом `PlantCatalog` строит меши по всем девяти видам, а `PlantSpecies`
держит породы для шести. То есть конвейер умеет больше, чем расстановщик просит.

Замер обхода V311: сосен 4574, кустов 55, **всех остальных ноль**.

**Вопросы:**

- один вид на пояс — сознательное упрощение под потолок производительности?
  В пояснении рядом стоит замер: девять вариантов формы дали 1359 групп, 4077
  узлов MultiMesh, 160 секунд построения и больше гигабайта памяти. Смесь видов
  умножит группы так же?
- какой бюджет считать пределом: сколько узлов MultiMesh и сколько памяти?
- покрытия (`GrassTuft`, `Moss`, `Stone`) заведены отдельным сортом с отдельной
  раскладкой (`IsCoverKind`, плотная постановка). Их ставили когда-нибудь на
  уровне или только в галерее растений? Если ставили — что помешало?
- цветы: раздел 2 называет их третьим по силе средством ввода мёртвых пигментов
  («россыпь мелких областей под красную, жёлтую, белую»). Почему их нет в
  расстановке — не дошли или пробовали и отвергли?
