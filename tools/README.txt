ИНСТРУМЕНТЫ ПРОВЕРКИ (не часть игры)
====================================

ВАЖНО: файлы стенда лежат с расширением .cs.txt намеренно.

Godot компилирует ВСЕ файлы .cs внутри каталога проекта, включая вспомогательные.
Два стендовых файла содержат по классу Program с методом Main — при обычном
расширении .cs это давало ошибки сборки:
    CS0101: namespace already contains a definition for 'Program'
    CS0111: type 'Program' already defines a member called 'Main'
Расширение .cs.txt выводит их из-под компиляции; для запуска на стенде файл
переименовывается обратно.

Ещё безопаснее — держать каталог tools ВНЕ каталога проекта Godot. Здесь он лежит
рядом только для удобства передачи.

СОСТАВ
------
syncheck.py            Синтаксическая проверка всех .cs через tree-sitter.
shadercheck.py         Проверка шейдеров: скобки, точки с запятой, недоступные
                       в Forward Mobile встроенные переменные, запись видовой
                       координаты в VERTEX без skip_vertex_transform.
make_foliage_atlas.py  Генерация атласа листвы (силуэты заданы формулами).
render_plants.py       Отрисовка отдельного растения без движка: перспективная
                       камера, z-буфер, отсечение по альфе атласа.
render_scene.py        Отрисовка уровня с камеры (рельеф, расстановка, полосы LOD).
render_scene_lib.py    Библиотека к render_scene.py.
read_level_sweep.py    Разбор телеметрии обхода уровня (клавиша T).
stand_sweep.py         Обход уровня на стенде — та же арифметика, что у клавиши T.

bench.zip              Испытательный стенд на C# — три проекта, см. ниже.
                       АРХИВОМ НАРОЧНО: распакованный ломает сборку игры.

StandSceneExport.cs.txt    Выгрузка сцены из стенда для render_scene.py.
StandSkeletonCheck.cs.txt  Сверка скелета дерева без листвы: углы отхождения
                           ветвей и зимний силуэт.

ИСПЫТАТЕЛЬНЫЙ СТЕНД: bench.zip
------------------------------
Стенд лежит здесь АРХИВОМ, а не файлами, и по той же причине, что и .cs.txt выше:
в нём три класса Program с методом Main, а GodotStubs.cs объявляет собственное
пространство имён Godot. Распакуй его сюда — и сборка игры упадёт на CS0101.

Распаковывать НАДО ВНЕ каталога проекта.

Внутри три проекта:
    routes/      сеть велосипедных маршрутов: опоры у местности, рёбра
                 анизотропным поиском с масками направлений. Замер и картинка.

    gentest/     слой Domain + Infrastructure/Generation целиком. От Godot не
                 зависит, поэтому собирается и ЗАПУСКАЕТСЯ. Здесь же Ringgen.cs —
                 точная копия построения колец дальнего фона без Godot. Копия
                 сверена с выгрузкой игры и сходится БИТ В БИТ; ею можно
                 подбирать что угодно, не гоняя игру. Пользоваться копией
                 разрешено только после такой сверки.
    cstest/      быстрый прогон отдельных алгоритмов; Render.cs выводит
                 затенённый рельеф в BMP без зависимостей.
    godotcheck/  проверка кода, ЗАВИСЯЩЕГО от Godot, по заглушкам типов движка.
                 Заглушек хватает, чтобы собирать целиком FarBackground.cs,
                 SeasonColorMapper.cs и TerrainGradient.cs.

Развернуть:
    unzip bench.zip -d ~/bench && cd ~/bench
    sh подготовить.sh <путь к каталогу проекта>
    cd gentest && dotnet run

NuGet из песочницы недоступен, поэтому в каждом проекте лежит nuget.config с
пустым списком источников. Без него сборка падает на попытке достучаться до
api.nuget.org.

ПРАВИЛО. Каждый раз, когда ошибка сборки всё-таки дошла до игры, — дополнить
GodotStubs.cs так, чтобы стенд её воспроизводил, и убедиться, что воспроизводит.
Иначе она повторится.


ЗАПУСК ОСТАЛЬНОГО
-----------------
Каталоги Domain и Infrastructure/Generation не зависят от Godot и собираются
обычным dotnet build. Нужный файл .cs.txt переименовывается в Program.cs проекта
стенда, после чего dotnet run.
